# 排序强化与后续计划

## 本次实现

54 张 flow 卡片继续使用各自的 strategy 配置。排序从“单分数排序 + tempo 交换”变为“策略结构初排 + 多维位置代价 + 邻接过渡优化”。

1. **方向型卡片**：能量、节奏、温暖、忧郁、亲密、张力等分别匹配沿途目标，按策略权重参与；目标范围来自当前歌单。修复非 wave 策略的 `0.5` 权重被忽略。
2. **稳定型卡片**：降低位置目标权重，让实际邻接跳变成本主导；沿用各策略不同的 tempo、情绪、攻击性惩罚。
3. **波浪型卡片**：按歌单长度控制周期数，目标振幅适配现有歌曲范围，再限制结构位置偏移。
4. **高潮型卡片**：peak-centered 也执行高潮区间初排；clusterRun 的最强歌曲集合在优化中不得与集合外歌曲交换。
5. **结尾型卡片**：保护柔和尾段与最终收束曲；Grand Finale 保留最强高潮曲作为终曲。
6. **章节型卡片**：保留现有聚类与叙事，优化只在章节内交换，边界过渡成本仍纳入评价。
7. **循环型卡片**：last → first 与内部过渡一起参与优化。
8. **数据完整性**：结构重排按条目位置识别重复歌曲，避免以歌曲 ID 过滤时丢失重复条目。

优化器最多四轮，每首歌查看后续 23 个位置，交换时只重算受影响位置与边；这是确定性的局部搜索，不是全局最优证明。波浪初排等已有步骤仍有二次复杂度。没有新增依赖或外部服务。

## 验证范围

- 全部 54 张单卡、同类型内全部 135 个双卡组合：输入不变、条目完整、确定性、过渡数量。
- 空歌单、1/2/3/5/8 首、重复条目；300 首 Deep import 规模。
- 合成特征上的方向升降、多个波峰、连续 banger 区间、最强结尾、章节成员保护。
- 稳定与循环策略在受控 fixture 中降低过渡代价。

上述测试验证算法性质，不等同于 54 种真实听感均经过人工试听。卡片中歌词叙事、声线、器乐和 drop 等细粒度承诺仍受特征数据限制。输入没有所需情绪跨度时，排序无法创造缺失的音乐特质。

## 建议后续优先级

### P0：特征可信度与可解释性

- 当前 `prototype-analysis.ts` / `audio-features/prototype-features.ts` 使用 metadata、关键词和确定性伪随机估计；先接入用户选定的真实特征来源，再做听感结论。
- Lyrical Focus 需要歌词叙事特征；Smooth Vocal Journey 需要声线/音色；Acoustic Landing 需要 acousticness；Drop Journey 需要段落结构。现有能量和情绪代理不足以证明这些维度。
- 结果页面按“有证据的特征、低置信估计、不可判断”显示；解释由实际前后差值驱动，避免将尖锐跳变自动解释为 deliberate gear-shift。
- 为每张卡建立独立的听感评价集：真实特征标注、盲听成对比较、符合描述比例。不能用相同排序公式生成期望答案。

### P1：用户控制与组合策略

- 给用户固定首尾曲、锁定位置、撤销、比较原序和新序的能力。
- 双卡显示结构和结尾的冲突处理，例如高潮优先还是收束优先；目前沿用 registry 的合并规则。
- 将 phase / ribbon 与实际局部走势统一。部分策略依然使用按位置分段的 Intro / Peak / Outro，不应把标签当成实际峰值证明。
- 将 `0.5` 的 wave 哨兵升级为显式曲线字段，避免组合权重恰好等于 0.5 时产生歧义。

### P2：工程与性能

- 长歌单优化移入 Web Worker，增加取消与真实进度；目前排序仍从 React provider 同步调用。
- 接通顶层 `tests/` 与 `src/lib/__tests__/` 的统一测试入口；当前 npm test 仅运行后者。
- 整理未跟踪的旧 `Flowlist.jsx` 原型；它目前导致全仓 lint 失败，本次未修改这个用户文件。
- 在有实际性能数据后增加特征/边代价缓存与结果列表虚拟化。
